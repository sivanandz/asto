## 2026-05-20 - Fix predictable PRNG in tarot entropy system
**Vulnerability:** The application was using the standard insecure `math.Random` seeded with custom entropy (accelerometer/gyroscope data combined with time) for tarot card draws. When sensor entropy was low (e.g., stationary device), the PRNG seed became heavily reliant on time, making card draws somewhat predictable and lacking cryptographic security.
**Learning:** Even when incorporating "physical" entropy from sensors to create a "magical" feel, using a non-secure PRNG initialized with predictable data points undermines the randomness. The absolute value of combined entropy sources can be safely added to a cryptographically secure random value and then modulo'd by the maximum range to retain both the unpredictable nature of `math.Random.secure()` and the physical entropy from device sensors.
**Prevention:** Always use `math.Random.secure()` for randomized systems like card draws where predictability can diminish application value or trust. Any custom entropy sources must be combined securely with a cryptographically secure PRNG instead of seeding an insecure generator.
