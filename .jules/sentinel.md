## 2025-05-09 - Predictable PRNG in security context
**Vulnerability:** The application was using weak pseudo-random number generation (`math.Random` seeded with predictable `DateTime.now()` and sensor data) to randomly choose logic that feels "magical", like picking tarot cards, meaning the order could potentially be guessed if seeded inputs were known.
**Learning:** Even for non-critical "fun" logic, generating entropy with non-secure randoms when a secure one (`math.Random.secure()`) is available limits the cryptographical sturdiness of an app, specially on systems that should prioritize entropy. We also shouldn't instantiate secure random generators inside loops (it's inefficient).
**Prevention:** Always use `math.Random.secure()` as the source base for PRNG tasks, and instantiate it outside generation loops if multiple unique integers are required. If we want to maintain the "physical feel" of the original code, safely mix the sensor entropy using modular addition.
