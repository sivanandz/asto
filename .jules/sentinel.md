## 2024-05-17 - Insecure PRNG Seed in EntropyRandom
**Vulnerability:** The application used `math.Random(mixedEntropy)` with a seed partially based on device sensors and current time to draw tarot cards and calculate fortunes. The base `math.Random` class is not cryptographically secure and a known seed makes its sequence entirely predictable, undermining the randomness requirement for fair and secure outcomes in the app.
**Learning:** Even when incorporating "entropy" from device sensors, passing the value as a seed to a weak PRNG algorithm does not guarantee cryptographically secure randomness. The random class state can be easily recreated by a bad actor who controls or observes the sensor and time state.
**Prevention:** Always use `math.Random.secure()` when outcomes must not be predictable, such as with drawing objects or assigning unpredictable values. To still incorporate the sensor and time data without introducing weak PRNG implementations, apply the absolute value of the custom entropy directly against the modulus result of `math.Random.secure()`, like `(math.Random.secure().nextInt(max) + entropyValue.abs()) % max`.
