## 2024-05-24 - Dart Performance Bottlenecks and Anti-Patterns
**Learning:** Dart's exception handling (`try-catch`) is relatively expensive and shouldn't be used for standard control flow, such as `Iterable.firstWhere` when an element may not be found. Returning `null` directly using a standard `for` loop avoids this overhead. Additionally, `CustomPainter` re-evaluates variables and collections on every paint. Using `final` for static lookup maps allocates a new object on every frame; these should be `const` instead. Unnecessary `shouldRepaint => true` calls lead to massive over-rendering.
**Action:** Replace `try-catch` blocks around `firstWhere` with `firstOrNull` (or standard `for` loop). Mark static layout maps within `CustomPainter` as `const` rather than `final`. Always accurately implement `shouldRepaint` based on object ID equality rather than hardcoding `true`.
