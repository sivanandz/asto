## 2024-06-08 - O(N) operations in CustomPainter Render Loops
**Learning:** Found a critical performance bottleneck in `VedicChartPainter` (`lib/components/vedic_chart_widget.dart`). The codebase was executing an O(N) `.where()` list filtering operation (`chart.positions.where((p) => p.house == actualHouse)`) inside a nested 3x3 loop during the `paint` method. Because `CustomPainter.paint` runs frequently (e.g., during animations or repaints), placing O(N) filtering inside nested loops causes significant CPU overhead and frame drops in Flutter.
**Action:** When implementing or optimizing Flutter's `CustomPainter` classes, avoid O(N) operations like `.where()` list filtering inside the `paint` method or rendering loops. Always pre-group data into Hash Maps (`Map<Key, List<Value>>`) outside the loops (or ideally outside the `paint` method entirely) to allow for O(1) lookups during rendering.
